# ChatGPT 用量小组件 · Scriptable

用于 iPhone 的 2×2 主屏幕小组件，显示 ChatGPT 订阅中的 **Codex 用量**。脚本文件为 `ChatGPT Usage.js`。

点击整块小组件后，Scriptable 会运行脚本、重新请求用量并显示最新预览。右下角显示半透明背景 Logo，按每次运行时的系统深浅色生成，登录凭据保存在 Scriptable 的钥匙串中。

## 安装与首次登录

1. 在 iPhone 安装或更新 **Scriptable**。
2. 打开 `ChatGPT Usage.js`，复制全部代码。
3. 在 Scriptable 点击右上角 **＋**，粘贴代码，把脚本命名为 **ChatGPT Usage**，保存后运行。
4. 首次运行会弹出设备码。点击 **复制设备码并打开授权页**，脚本会复制设备码并打开 OpenAI 官方页面 `https://auth.openai.com/codex/device`。
5. 在页面中登录 ChatGPT，粘贴设备码并完成授权。如果页面要求启用设备码登录，按提示在 ChatGPT 的安全设置中启用。
6. 授权完成后，点击浏览器的 **完成**，回到 Scriptable。脚本会查询授权结果、保存登录凭据、获取用量，并显示小尺寸预览。
7. 如果仍显示设备码，先确认网页已完成授权，再运行一次脚本。设备码约 15 分钟有效，超时后重新运行会申请新码。

如果 iOS 在网页登录期间结束了脚本，重新打开 Scriptable 运行同一脚本即可继续查询授权结果。首次使用本脚本需要在 Scriptable 中完成一次授权。

## 添加到主屏幕

1. 长按 iPhone 主屏幕空白处，选择添加小组件。
2. 搜索 **Scriptable**，选择小尺寸 **2×2** 并添加。
3. 长按新组件 → **编辑小组件**，在 **Script** 中选择 **ChatGPT Usage**。
4. **When Interacting** 选择 **Run Script**；**Parameter** 留空。脚本本身也设置了运行当前脚本的点击链接。

脚本包含图标，无须另外下载图片或填写 API Key。

## 点击刷新怎么用

直接点击主屏幕上的整块组件：

**进入 Scriptable → 自动请求最新用量 → 显示更新后的预览 → 手动返回桌面。**

每次运行都会请求用量接口。请求成功后保存新数据，并调用 `Script.setWidget()` 提交组件内容；前台运行时还会把 `refreshAfterDate` 设为当前时间，申请尽早更新。

**桌面小组件立即重绘仍需在你的 iPhone 上实测。** iOS 控制实际刷新时机，前台预览更新成功不代表桌面一定同步完成。如果预览已更新、桌面仍显示旧时间，说明新数据已经取得，桌面还在等待刷新。

2×2 小组件按 Scriptable 的接口使用整块点击区域。登录有效时点击刷新；尚未登录或凭据失效时，点击进入登录流程。

底部的更新时间显示到分钟。同一分钟内连续刷新，显示的时间可能相同；验证点击效果时，可以间隔一分钟再点。用量没有增加时，百分比本身也可能保持不变。

后台正常申请约 15 分钟后刷新，实际间隔由 iOS 决定。登录页面和预览只会在前台运行时打开。

## 外观与显示规则

脚本开头保留可修改的外观常量：

```js
const LOGO_OPACITY = 0.03;
const LOGO_RATIO = 0.85;
const LOGO_OFFSET = -0.11;
const BACKGROUND_LIGHT = '#FFFFFF';
const BACKGROUND_DARK = '#14211B';
const PADDING_VERTICAL = 12;
const PADDING_HORIZONTAL = 14;
```

- `BACKGROUND_LIGHT` 和 `BACKGROUND_DARK` 分别控制浅色、深色模式的组件背景。
- 第一行左侧是 18 点粗体 ChatGPT 标题，右侧是套餐，如 `Pro 5x`、`Plus`。
- 每个限额周期一行：左侧是周期名称（`Weekly`、`5h`），右侧是已用百分比；下方是 20 格竖条进度条，每格代表 5%，已用格为实色、未用格为浅色；再下方是重置时间。
- 底部一行：左侧是最后成功更新时间，右侧是状态，如 `未登录`、`等待授权`、`登录已过期`、`网络异常`。正常时右侧留空。
- 背景 Logo 的边长为组件边长的 85%，右／下偏移均为 -11%，不透明度为 0.03，超出部分裁切。
- 浅色使用黑色 Logo，深色使用白色 Logo。切换系统外观后，背景需等待脚本重新运行，桌面更新时间由 iOS 决定。
- 上下内边距保持 **12**，左右保持 **14**。更新时间和重置时间均居左。
- 低于 95%：数字与进度条使用蓝色，浅色 `#3A83F7`，深色 `#75A7FF`；达到或超过 95% 时，两者同步变为橙色作提醒，浅色 `#DC6F0C`，深色 `#FFA94D`。「登录已过期」使用红色。
- 仅有一个限额周期时显示较大的百分比和较高的进度条；接口返回两个周期时分别显示。没有返回 5 小时窗口时，不额外添加。
- 接口未返回窗口时显示「未返回限额窗口」，不推断为零用量或无限额度。
- 距离重置少于 24 小时，显示 `重置 2小时13分`；达到或超过 24 小时，显示 `重置 09/21 20:20`。
- 所有时间均为 **Asia/Taipei（GMT+8），24 小时制**。倒计时文字在脚本运行时计算。
- `更新 19:20` 是最后一次成功获取并保存用量的时间；跨日显示 `更新 09/17 19:20`。失败不会推进这个时间。
- 重置时刻已过但尚未取得新数据时，显示「重置待确认」，保留最后一次成功的读数。

[`previews/chatgpt.html`](../../previews/chatgpt.html) 使用示例数据，可查看单周期、双周期、深浅色、95% 阈值和登录／错误状态。浏览器近似呈现脚本布局，实际字体与尺寸以 iPhone 为准。

## 登录过期与故障排查

脚本会在访问令牌将要过期或接口返回 401 时尝试续期。只有明确的凭据失效才显示「登录已过期」；点击小组件后重新授权即可。

网络异常、403 访问受限、429 请求过多、服务器错误和响应格式异常会显示不同提示，并保留最后一次成功用量及原更新时间。

| 现象 | 检查方式 |
| --- | --- |
| 点击后只有 Scriptable 首页 | 确认组件选择了此脚本，并把 When Interacting 设为 Run Script；在 App 内手动运行一次确认脚本已保存完整。 |
| 预览更新、桌面没有变化 | 新数据已经获取，桌面可能仍在等待 iOS 调度。观察桌面底部成功更新时间。 |
| 显示网络异常或访问受限 | 在 Scriptable 内运行脚本，检查手机当前网络能否访问 ChatGPT 及 OpenAI 授权页面。填写了代理地址时，确认手机能访问该代理，且它把对应路径转发到官方地址。 |
| 登录后仍显示设备码 | 确认网页授权完成，点击浏览器的完成回到脚本；必要时在设备码有效期内再运行一次。填写了 `PROXY_AUTH_URL` 时，确认该地址转发到 `https://auth.openai.com`。 |
| 显示脚本运行异常 | 在 Scriptable App 内运行脚本。错误弹窗会显示阶段、具体报错和可用的引擎行号；点击「复制错误信息」可复制排查信息。 |

前台运行日志记录结果、失败阶段和成功更新时间；发生脚本运行异常时，同时记录脱敏后的具体报错并弹窗显示。需要查看保存的诊断记录时，可临时新建另一个 Scriptable 脚本，运行以下代码：

```js
const key = 'chatgpt.usage.v1.status';
console.log(Keychain.contains(key) ? Keychain.get(key) : '暂无请求记录');
```

其中 `checkedAt` 是最近一次尝试的 Unix 毫秒时间戳，`stage` 是执行阶段，`kind` 是结果，`httpStatus` 是 HTTP 状态码，`detail` 是脚本运行异常的具体原因。此记录不包含令牌或钥匙串原文。登录凭据与正在授权的设备信息也保存在钥匙串中，不会写入脚本文件或日志。如果钥匙串本身无法访问，前台错误弹窗仍可用于排查。

## 可选：经反向代理转发请求

脚本默认直接请求 OpenAI 官方接口。自己部署了反向代理（例如 [api-proxy](https://github.com/lainbo/api-proxy)）时，可以让设备码申请、授权查询、令牌续期和用量请求经代理发出。访问令牌会随请求经过代理，只应使用自己控制的代理。授权网页仍在 Safari 中直接打开 OpenAI 官方地址。

在 Scriptable 中打开本脚本，填写开头的两个常量并保存。每个值是代理上转发到对应官方地址的完整地址，包含路径；脚本只在其后拼接接口路径，末尾的斜杠会被去掉。以 api-proxy 的路由为例：

```js
const PROXY_AUTH_URL = 'https://proxy.example.com/openai-auth';  // 代替 https://auth.openai.com
const PROXY_CHATGPT_URL = 'https://proxy.example.com/chatgpt';   // 代替 https://chatgpt.com/backend-api
```

这时用量请求发往 `https://proxy.example.com/chatgpt/wham/usage`。只填写其中一项时，另一项继续直连官方接口。`PROXY_AUTH_URL` 没有正确转发时，授权查询收到的 404 会被当成仍在等待授权。改回 `''` 即恢复直连。重新粘贴新版脚本时这两行会恢复为空，需要再次填写。

## 代码维护

脚本保持单文件，业务逻辑采用函数式组织：数据转换与显示计算使用纯函数，登录、请求、存储和界面操作由流程函数串联。计算所需的当前时间通过参数传入，状态更新返回新对象。Scriptable 原生对象仍按其 API 要求创建。

## 验证范围

已完成 JavaScript 语法检查，并通过电脑端的 Scriptable 请求接口适配，实际验证了用量接口返回 200、设备码申请和未授权状态查询。前台执行检查确认了请求、提交组件和展示预览的调用顺序；模拟断网时，原用量和成功更新时间保持不变。浏览器预览使用示例数据，在 158 与 170 点尺寸核对布局和主题颜色，包括当前的标题行、20 格进度条和底部状态布局。

在电脑上加载本脚本，分别在不填写代理地址、按线上 api-proxy 节点填写，以及按本机自定义路径前缀（如 `/relay/v2/oa-auth`）的转发器填写时，用 Codex 现有的访问令牌只读请求用量，返回 200 并正确解析；设备码申请返回 200，未授权查询返回 403 并判定为等待授权，无效续期令牌返回 401 并判定为登录过期，三种方式结果一致。不填写时请求全部发往官方地址，填写后全部发往所填地址的路径之下，末尾带斜杠的地址同样正确。填写代理地址后在 iPhone 上的运行尚待确认。

用户已在 iPhone 上确认：点击组件会进入 Scriptable，运行后能够更新用量。**仍需确认双周期布局在 iPhone 上的纵向空间、底部长状态文字是否正常缩小、App 重启后的钥匙串持久化、令牌自动续期、背景 Logo 的原生裁切、系统主题切换和后台刷新时机。** 电脑端适配执行不等同于 Scriptable 原生环境测试。交付文件不包含账号凭据。
